# Complete C Firmware Test Suite Plan — RISC-V Network Telemetry SoC

**Document status:** Consolidated implementation plan  
**Date:** 2026-10-17  
**Project:** RISC-V Network Telemetry SoC  
**Primary CPU:** VeeR EL2 RV32IMC  
**Firmware:** Bare-metal C with RISC-V GNU Toolchain  
**Build/simulation:** GNU Make → ELF → simulator-native memory images → VCS `simv` → logs/FSDB → Verdi  
**Verification principle:** Never claim PASS without reproducible log evidence. A failing test must produce a deterministic failure record and must not hang the simulation.

## Document purpose

This document consolidates the supplied execution plan with the broader test inventory needed to verify the SoC's memories, system bus, CPU-accessible peripherals, interrupt paths, and final telemetry application. The original execution plan remains included below as the implementation-specific baseline; the consolidated sections before and after it add the complete test taxonomy, acceptance criteria, dependency gates, and regression strategy.

## 1. Executive summary

The immediate gap is not a lack of standalone IP tests. It is the absence of a unified C firmware suite that runs on VeeR and accesses the peripherals through the actual SoC bus. The existing evidence distinguishes these paths:

- **Firmware path already demonstrated:** C → RISC-V GCC → ELF → `imem.mem`/`dmem.mem` → VeeR EL2 → system memory → VCS/FSDB/Verdi.
- **UART path already demonstrated separately:** VeeR → AHB fabric → AHB-to-AXI bridge → UART wrapper/IP → serial TX. The Phase 3 program was generated by a Python mini-assembler, not C firmware.
- **Standalone AES evidence exists:** AES AXI-wrapper tests and known-answer results exist, but AES is not connected to the current SoC AHB decode or `soc_top` according to the supplied 2026-10-17 repository audit.
- **Not yet implemented in RTL:** Timer, GPIO, Network Telemetry Engine, and CRC32. They must not be represented as currently testable C peripherals until RTL, address decode, and top-level integration exist.
- **ICCM/DCCM:** instantiated as VeeR core-local ECC memories, but access from the proposed C test mode is unresolved. Phase 0 is a permission/access spike; the frozen initial firmware architecture intentionally keeps ICCM/DCCM unused. Do not silently combine these two modes.
- **Interrupt delivery is absent, not merely untested:** `soc_top` exposes no interrupt input and no peripheral IRQ reaches the VeeR PIC, so all IRQ tests are **BLOCKED — RTL** (§5.10).

The plan therefore has two explicit scopes:

1. **Current implementation scope:** C-driven tests for boot/runtime, IMEM, DMEM, AHB decode/error behavior, and UART; ICCM/DCCM only if Phase 0 proves safe CPU access.
2. **Future full-SoC scope:** AES after an explicit integration change, and Timer/GPIO/Network/CRC after their RTL and bus integration are implemented and specified.

A test marked **BLOCKED** or **FUTURE** is part of the verification plan, not evidence that the corresponding hardware exists or has passed.

## 2. Architecture and verification boundaries

### 2.1 Verification layers

| Layer | Purpose | Required evidence |
|---|---|---|
| L0 — Firmware infrastructure | Boot, C runtime, assertion framework, timeout, result mailbox | ELF gates, deterministic test summary, intentional-failure demonstration |
| L1 — Memory and bus | IMEM, DMEM, safe address boundaries, AHB decode, stalls, ERROR response | Firmware read/write results plus bus monitor and selected waveform evidence |
| L2 — Existing peripheral | UART registers and TX behavior through the integrated VeeR path | UART transcript/serial monitor, AHB/AXI observations, no unexpected exceptions |
| L3 — Core-local memories | ICCM/DCCM access and memory patterns, only if Phase 0 allows | CPU-visible readback and bank-level waveform evidence; write-before-read |
| L4 — AES integration | AHB decode, bridge, AES AXI slave, IRQ, C driver | Fabric regression, AES known-answer vector, status/IRQ checks |
| L5 — Planned peripherals | Timer, GPIO, Network Telemetry Engine, CRC32 | RTL implementation, frozen register map, directed RTL tests, then C tests |
| L6 — System integration | Packet → telemetry/CRC → CPU → AES → UART | Independent packet/CRC/AES reference checks and complete E2E log |

### 2.2 Ownership of checks

- **C firmware:** software-visible register accesses, data comparisons, state-machine sequencing, interrupt service, timeouts, and result reporting.
- **SystemVerilog testbench:** packet stimulus, serial decoding, simulation watchdog, expected-trap observation, bus protocol checks, and independent scoreboards.
- **Verdi:** waveform-based diagnosis and evidence for failures or timing-sensitive claims.
- **Reference models:** expected CRC, AES ciphertext, packet fields, frame length, and serial bytes must be calculated independently of DUT outputs.

C tests do not replace the existing direct RTL regressions. Retain the fabric, UART, AES, and other IP-level tests as separate regression gates.

### 2.3 Status labels

Use these labels consistently in implementation tracking:

- **VERIFIED BASELINE:** supported by an existing log/record.
- **PLANNED:** test design exists, code has not been written.
- **BLOCKED — RTL:** required hardware or address decode does not exist.
- **BLOCKED — SPEC:** register semantics or bit definitions are not frozen.
- **CONDITIONAL:** run only after an explicit prerequisite passes.
- **PASS:** only after the defined token and evidence are present in a surviving log.

## 4. Global pass/fail contract

Every test must have a stable ID, a bounded completion time, an explicit expected result, and a result-table entry. A test may not report PASS merely because a load/store instruction completed.

For each test, record:

1. Test ID and descriptive name.
2. Result code (`0` = pass; nonzero = fail).
3. Failure code and relevant address/value when applicable.
4. Testbench-observed bus/serial/interrupt evidence where required.
5. Final suite status and simulation exit status.

The runner must continue or abort according to a documented policy; it must never silently swallow a failure. At minimum, a failure must set the aggregate result to FAIL, preserve the first failure index/code, and produce a nonzero final status. An intentionally failing test must prove that both UART reporting and the DMEM result table correctly capture the failure.

### 5.2 Memory tests

The initial firmware memory map is:

| Region | Address range | Size | Access constraints |
|---|---|---:|---|
| IMEM | `0x00000000–0x00007FFF` | 32 KiB | Never overwrite executing code or live `.rodata`; restrict writes to linker-declared safe scratch after the image. |
| DMEM | `0x00010000–0x00017FFF` | 32 KiB | Respect reserved result/mailbox area, `.data`, `.bss`, and descending stack. |
| ICCM | `0xEE000000` | 64 KiB | **NOT reachable from C** — IFU-driven (`el2_ifu_iccm_mem`); a C access routes to the AHB ERROR slave (§3) |
| DCCM | `0xF0040000` | 64 KiB | Reachable from C, verified 2026-10-17; LSU-driven (`el2_lsu_dccm_mem`); write before read, never assume reset-zero |

| ID | Test | Acceptance criterion |
|---|---|---|
| MEM-01 | IMEM boot/image integrity | Firmware executes and expected signature is observed. |
| MEM-02 | DMEM walking ones | Each of 32 bit positions writes and reads correctly. |
| MEM-03 | DMEM walking zeros | Complementary bit patterns read back correctly. |
| MEM-04 | Address uniqueness | Distinct address-derived patterns expose aliasing. |
| MEM-05 | Width sweep | Supported 8/16/32-bit accesses preserve expected lanes and neighboring bytes. |
| MEM-06 | Block fill/checksum | Fill and read back a bounded scratch region; checksum matches independent expected value. |
| MEM-07 | Retention sample | Values remain stable after unrelated accesses. |
| MEM-08 | Lower/upper boundaries | First and last legal aligned words behave correctly without touching reserved memory. |
| MEM-09 | Region isolation | Writes in one accessible region do not alter a separate region. |
| MEM-10 | ICCM access | **BLOCKED — RTL/ARCH.** Resolved 2026-10-17: ICCM is driven by the IFU (`el2_ifu_iccm_mem`, `el2_ifu.sv:149-152`), so a C load/store has no route to it and falls through to the AHB ERROR slave. Not a test — a routing fact. |
| MEM-11 | DCCM access | **UNBLOCKED.** Verified reachable 2026-10-17 (`dccm_rb=5a5a5678`, `def=0 bus_err=0`). Served by `el2_lsu_dccm_mem` from the LSU. 64 KB; write-before-read always, never assume reset-zero. |

A complete sweep is a long-running test. The simulation watchdog and waveform strategy must be updated before enabling full-region sweeps. Do not write a full sweep into IMEM unless the linker exports and enforces a safe region beyond the complete load image. Do not sweep DMEM over live stack or test results.

### 5.3.1 Verified error-propagation path (2026-10-17)

> **CORRECTION 2026-10-17 (Phase 3).** The section below was written from the
> Phase 0 observation that an ICCM access "trapped and parked". That was **not**
> a bus response error — it was an instruction-access fault. Measurement in
> Phase 3 settled the question: **an AHB ERROR response does not raise a trap
> at all.** `el2_lsu_lsc_ctl.sv:210` is the only producer of an LSU exception
> (`access_fault_m | misaligned_fault_m | lsu_double_ecc_error_m`); a bus
> response error is not in that list. It surfaces only as `lsu_pmu_bus_error`
> (`el2_veer.sv:923`), whose sole consumer is a PMU event hit vector
> (`el2_dec_tlu_ctl.sv:2651`). So a CPU-issued unmapped access **stalls the
> core**; it does not trap. The trap machinery is retained only for the one
> case that does trap — a PMP-denied access — and BUS-05/06/07 are verified at
> the fabric by the testbench (`+bus_watch`). See
> `doc/Phase3_Memory_and_Bus_Record.md` §2.

An AHB ERROR response **does** reach the CPU as an exception. Traced through the
frozen VeeR submodule:

| Stage | File | Behaviour |
|---|---|---|
| 1 | `rtl/ahb/ahb_default_slave.sv` | asserts `hresp` for the ERROR cycle |
| 2 | `core/Cores-VeeR-EL2/design/lib/axi4_to_ahb.sv:91` | `input ahb_hresp` |
| 3 | same, `:323`, `:344`, `:365` | `slvbuf_error_in = ahb_hresp_q` |
| 4 | same, `:264`, `:268` | `axi_bresp/axi_rresp = 2'b10` (SLVERR) or `2'b11` (DECERR) |
| 5 | `design/lsu/el2_lsu_bus_buffer.sv:873` | `bus_rsp_read_error = bus_rsp_read & (lsu_axi_rresp != 2'b0)` |
| 6 | same, `:785`, `:827`, `:913` | `buf_error` → `lsu_nonblock_load_data_error` / `lsu_imprecise_error_store_any` |
| 7 | `design/el2_veer.sv:923` | `lsu_pmu_bus_error` → imprecise exception |

Consequences for BUS-10:

- **The CPU-issued layer is viable.** Firmware touching an unmapped address
  really does trap, so the claim "the CPU takes a bus exception" is testable.
- **The exception is IMPRECISE**, so **`mepc` must not be used to resume.**
  `mepc + 4` is unsafe: for an imprecise store error, `mepc` does not reliably
  identify the faulting instruction.
- **Resume by fixed label.** The expect-flag trap handler must clear the flag
  and jump to a known-safe label in `main`, not to a `mepc`-derived address.
  This is more robust and removes `mepc` semantics from the test design.
- **For a store to an unmapped address the data outcome is undefined** and does
  not matter, because the address is not backed by anything.
- **The `AHB_RW_MONITOR` equality gates are real.** `bus_err` and `def_sel`
  increment on these deliberate accesses, so §5.3 tests must run with the
  expected-error counts set (see §7).

### 5.3.2 PMP default is allow-all (verified 2026-10-17)

`build/snapshots/p2_soc/perl_configs.pl:562` sets `pmp_entries = 16`, so
`el2_lsu_addrcheck.sv:170` takes the `pt.PMP_ENTRIES > 0` path and uses
`lsu_pmp_error_start|lsu_pmp_error_end` rather than region-population logic.
All PMP entries reset with `pmp_pmpcfg[r].mode == OFF`, which makes
`region_match_all[c][r] = 1'b0` (`el2_pmp.sv:251`); in
`access_fault_check` (`el2_pmp.sv:167-178`) no entry matches, `matched` stays
`0`, and `access_fail` remains `1'b0`.

**Therefore the PMP permits every access by default**, and unmapped addresses
reach the AHB fabric rather than faulting inside the LSU. This is what makes
BUS-05/06/07 meaningful and it also means firmware needs to program no PMP
registers to run this suite.

Also verified: misaligned access to a side-effect region faults
(`el2_lsu_addrcheck.sv:224-225`), so all MMIO accesses in this suite must be
naturally aligned, and MEM-05 must not issue misaligned accesses to IMEM/DMEM
without treating a fault as the expected result.

### 5.4 UART tests

**Implemented address:** `0x10000000`. The UART wrapper's currently served register reads are limited: RBR/THR at offset `0x00` and LSR at `0x14` reach the UART IP; reads of IER, BAUD and LCR are locally returned as zero by the wrapper. Assert this behavior only while that wrapper contract remains unchanged.

| ID | Test | Acceptance criterion |
|---|---|---|
| UART-01 | Idle/reset status | LSR reports THRE and TEMT when idle (`0x60` under the audited implementation). |
| UART-02 | Single byte | Testbench decodes the expected byte from `uart_tx_o`. |
| UART-03 | Fixed string | Serial monitor matches every byte and order. |
| UART-04 | THRE polling | Firmware polls the documented ready bit with a timeout before writing. |
| UART-05 | TEMT completion | Firmware waits for final shift-register drain before reporting completion. |
| UART-06 | Back-to-back payload | No loss, duplication or reordering. |
| UART-07 | FIFO stress | Exercise the implemented FIFO depth (audited value: 32) without assuming unsupported behavior. |
| UART-08 | Baud configuration | Apply DLAB/divisor sequence and verify actual serial timing; audited suite should use BAUD=8 to keep simulation duration manageable. |
| UART-09 | Wrapper read behavior | IER/LCR/BAUD reads return zero under the present bypass behavior. |
| UART-10 | TX-only IRQ behavior | `uart_irq` remains low for the current TX-only integration contract. |
| UART-11 | RX limitation | RX testing remains blocked while `soc_top` ties `uart_rx_i` high; do not claim RX coverage. |

The existing Phase 3 test sends `UART\\n` using a Python-generated instruction program. Preserve it as a regression and add a C-driven version. UART output can dominate simulation time, so use concise logs and a fast simulation baud configuration.

|---|---|---|

| AES-03 | Known-answer vector | Ciphertext matches the standard AES-128 reference vector below. |
| AES-04 | Word/byte ordering | Four register words map correctly to 128-bit key, plaintext and ciphertext. |
| AES-05 | Completion interrupt | IRQ asserts on completion and clears by the specified control operation. |

| AES-07 | Repeated operations | Back-to-back transactions do not reuse stale status/results. |

Reference vector:

```text
Key:        000102030405060708090a0b0c0d0e0f
Plaintext:  00112233445566778899aabbccddeeff
Ciphertext: 69c4e0d86a7b0430d8cdb78070b4c55a
```

The wrapper's word convention is `key = {KEY3, KEY2, KEY1, KEY0}` and `aes_text_in = {DATA3, DATA2, DATA1, DATA0}` according to the supplied execution plan. The C driver must explicitly account for this ordering.

### 5.11 End-to-end acceptance

This is the final stage and is blocked until the relevant hardware exists and is integrated.

1. C firmware configures the implemented peripherals.
2. Testbench injects an Ethernet frame using the defined 8-bit streaming interface.
3. Telemetry logic produces packet metadata and counters.
4. CRC/FCS logic validates the received frame independently.
5. Firmware services the packet event and builds the frozen 128-bit telemetry record.
6. AES encrypts the record; firmware verifies the known expected ciphertext and completion event.
7. UART reports packet statistics, CRC status and ciphertext.
8. Testbench compares UART bytes and all expected intermediate values; final mailbox and regression tokens indicate PASS.

Required scenarios include a valid frame, corrupted payload/FCS, unsupported EtherType, boundary lengths, `pkt_valid` gaps, back-to-back packets, interrupt clear/re-arm, and AES known-answer coverage. Do not claim the complete application is implemented until the integrated C-driven test and its independent scoreboard pass.

## 6. Build, run, and regression policy

Preserve the frozen image flow: ELF → simulator-native memory image → testbench-owned image loading. Intel HEX is a delivery artifact only and must not be passed to `$readmemh`. Keep the existing `run/*.csh` reference flows intact while adding new Make targets.

Existing gates G1–G13 must remain green. The supplied execution plan proposes G14 for undefined-symbol checking and G15 for IMEM image/scratch safety. New targets such as `make test-memory` or `make test-e2e` are proposals and must not be described as existing until wired into the root Makefile.

Recommended command progression:

```bash
make -C sw clean all inspect
make sim
# Proposed targets after implementation:
make test-memory
make test-uart
make test-bus
make test-all
# Later, after required RTL integration:
make test-aes
make test-timer
make test-gpio
make test-telemetry
make test-crc
make test-interrupts
make test-e2e
```

Every target must return nonzero when a test fails. The simulation flow must gate on the existing firmware completion and AHB monitor tokens as well as the new test-suite result. A testbench timeout, missing token, unexpected exception, bus error, or UART mismatch must fail the run.

## 6.1 Locked build strategy — compile-time test selection (2026-10-17)

Each per-area target needs a **distinct firmware image**. A single image cannot
gate `test-memory` independently, and memory sweeps are the slow part, so
isolation is worth the build cost.

**Mechanism:** a compile-time selection macro plus one build directory per
variant, over a single shared `simv` binary.

```make
# sw/Makefile
TEST_SELECT ?=
TEST_SELECT_CFLAGS := $(if $(TEST_SELECT),-DTEST_SELECT_$(TEST_SELECT))
```

`tests/test_main.c` then includes only the selected group, guarded by
`#ifdef TEST_SELECT_MEMORY` and friends. Build directories:

| Target | `BUILD` dir | Selected tests |
|---|---|---|
| `test-memory` | `sw/build/mem` | `TEST_SELECT=memory` |
| `test-uart` | `sw/build/uart` | `TEST_SELECT=uart` |
| `test-bus` | `sw/build/bus` | `TEST_SELECT=bus` |
| `test-all` | `sw/build/all` | `TEST_SELECT=all` (or empty = everything) |

**Why one shared `simv` is enough:** `$readmemh` runs in an `initial` block at
t=0, so re-running the same elaborated binary against a different
`p2_prog.hex` in the same working directory picks up the new image without
re-compilation. `sim/Makefile` already parameterises `WORK`, so each target is
`build <variant image>` → `cp <variant>/imem.mem $WORK/p2_prog.hex` →
`./simv` → grep tokens.

## 6.2 Locked bus-monitor strategy — expected-error counts (2026-10-17)

`tb/tb_ahb_cycle_monitor.sv:110-113` currently gates on **equalities**:

```systemverilog
pass = (imem_rd >= N_IMEM_RD) && (dmem_rd >= N_DMEM_RD) &&
       (dmem_wr >= N_DMEM_WR) && (bus_err == 0) && (def_sel == 0);
```

BUS-05/06/07 deliberately drive `def_sel` and `bus_err` (see §5.3.1), so those
runs would fail `AHB_RW_MONITOR: PASS`, which §9 requires to remain present.
**Decision: parameterize the monitor rather than weaken it.**

Add `N_EXPECT_DEF` and `N_EXPECT_BUSERR` (both default `0`, preserving today's
behaviour exactly) and change the two equalities to:

```systemverilog
(bus_err == N_EXPECT_BUSERR) && (def_sel == N_EXPECT_DEF)
```

Each test set declares its own expectation: `test-bus` expects the precise
count of deliberate unmapped accesses; `test-memory`, `test-uart` and
`test-all` keep `0`. The `FAIL reason:` diagnostics must also be updated so an
unexpected count reports as a mismatch rather than as "!= 0".

## 7. Runtime, waveform, and toolchain constraints

- **MMIO polling:** use `volatile` accesses and configure VeeR MRAC side-effect behavior for the UART region before polling. The exact CSR setup must be validated against the VeeR PRM and current configuration.
- **Core-local memories:** ICCM/DCCM have no guaranteed reset contents; write before read and do not assert reset-zero.
- **Toolchain:** audited GCC 16.1.0 has RV64-only `libgcc` and no RV32 multilib. RV32 32-bit division/modulo and variable shifts linked in the audit, but 64-bit division/modulo fails with unresolved `__udivdi3`. Keep test arithmetic 32-bit unless runtime support is intentionally added.
- **Simulation duration:** full memory sweeps can take orders of magnitude longer than fw0. Raise the watchdog and timeout before enabling sweeps.
- **FSDB size:** routine runs should avoid unbounded full-signal dumps. Gate waveform capture behind an explicit `+wave`/debug option or constrain dump scope; enable focused waveform evidence when diagnosing a failure.
- **UART duration:** use a simulation-appropriate baud divisor (the supplied plan specifies BAUD=8) and compact output, while ensuring the testbench correctly calibrates the serial bit period.
- **Expected AHB ERROR:** unmapped accesses raise **imprecise** exceptions (§5.3.1). Implement a flag-guarded trap handler that resumes at a **fixed safe label** — never `mepc`-derived — before adding normal-flow decode tests. `tb_ahb_cycle_monitor` needs its expected-error counts parameterized (§6.2).
- **No PMP setup required:** the PMP allows all by default (§5.3.2), so firmware programs no PMP registers for this suite.
- **Alignment:** misaligned access to a side-effect region faults (§5.3.2). Keep all MMIO accesses naturally aligned and do not treat a misaligned IMEM/DMEM access as a normal result.
- **No interrupt path:** `soc_top` has no interrupt input and no peripheral IRQ reaches the PIC (§5.10), so all IRQ tests are BLOCKED — RTL. UART-10 is a TB pin observation only.
- **IMEM safety:** test scratch must begin after the complete image/load range and be enforced by linker/build gates.
- **DMEM safety:** reserve the results table explicitly; exclude `.data`, `.bss`, active stack and mailbox from destructive patterns.

# 2. Constraints that shape the design

## 2.1 ICCM/DCCM have no reset value — write before read

`tb/tb_veer_p2_soc.sv:221-246` instantiates `ram_4096x39` with no init file and
no reset on `Q`. Any location never written by the core reads back as `X`.

**Rule:** the suite must never assert "reads as zero" for ICCM/DCCM, and every
read must be preceded by a write to that location. ECC is self-consistent
because the core writes its own computed 7-bit ECC in and reads it back
unchanged (`{iccm_bank_wr_ecc, iccm_bank_wr_data}` in, `{bank_ecc, bank_dout}`
out); `iccm_ecc_single_error`/`dccm_ecc_single_error` are tied off at
`tb_veer_p2_soc.sv:181-182` regardless.

## 2.2 MRAC must be programmed or MMIO silently disappears

VeeR's LSU load buffer will forward repeated polls of the same load address.
Without `MRAC` bit 3 the repeated LSR polls never reach the bus, and the
monitor reports `uart_rd=0`.

**Rule:** `sw/src/startup.S` must set `MRAC` bit 3
(`MRAC_UART_SIDE_EFFECT = 1 << 3`, CSR address `0x7C0`) and issue `fence.i`
before any MMIO access. Reference: `scripts/p3_uart_prog_gen.py:28-33`. The
current `startup.S` never touches MRAC. MRAC has no hardware reset value.

## 2.3 The simulation budget is ~22x too small

| Quantity | Value |
| --- | --- |
| Core clock | 10 ns period, `tb_veer_p2_soc.sv:23` (`always #5`) |
| fw0 completion | 90,915 ns (`build/sim/fw0/sim.log`) |
| Current monitor watchdog | 1,900,000 ns (`tb_veer_p2_soc.sv:329`) |
| Current TB timeout | 2,000,000 ns |

A 32 KB sweep is ~16K writes + ~16K reads. At roughly 4–8 cycles per AHB
transaction that is ~2 ms of sim time **per memory per pattern**. Four memories
× several patterns lands in the 50–200 ms range — roughly 25–100× the current
budget.

**Rules:** (a) `WATCHDOG_NS` and the `#2000000` timeout must both be raised by
~100×; (b) FSDB must be compressed or narrowed, or the run will emit a
multi-GB waveform; (c) UART must be programmed with `BAUD = 8`, not the reset
default `868`, or each log line costs ~350 µs of sim time.

```c
/* A test returns 0 on pass, nonzero on fail; the value is the fail code. */
```

## 5.1 `sw/src/uart.c` — new

Register map, from `rtl/uart/uart_axi_slave.v:141-149`:

| Register | Offset | Abs | Notes |
| --- | --- | --- | --- |
| THR / RBR | `0x00` | `0x1000_0000` | WO TX / RO RX |
| IER | `0x04` | `0x1000_0004` | bit 0 IRQ enable; **reads bypassed to 0** |
| BAUD | `0x08` | `0x1000_0008` | divisor when DLAB=1; **reads bypassed to 0** |
| LCR | `0x0C` | `0x1000_000C` | bit 7 DLAB, 2 stop, 3 parity en, 4 parity mode; **reads bypassed to 0** |
| LSR | `0x14` | `0x1000_0014` | bit 0 DATA_READY, 5 THRE, 6 TEMT — **the only status read served** |

The bypass is deliberate, from `uart_axi_slave.v:153-156`:

```systemverilog
function automatic logic is_ip_read_offset(input [4:0] off);
    is_ip_read_offset = (off[4:2] == 3'd0) || (off[4:2] == 3'd5);
endfunction
```

Only RBR/THR and LSR reach the IP; every other read completes locally with
`32'h0000_0000`. The suite asserts these return 0 as **expected behaviour**,
so a future RTL change that starts honouring them fails the suite loudly.

`uart_init()` must program `BAUD = 8` (§2.3c), via the DLAB set/latch/clear
sequence: `LCR |= 0x80` → `BAUD = 8` → `LCR = 0x03` (8N1).

Note the latching quirk at `axi_uart_top.v:408`: `AckWriteState` does
`uart_baudrate_div_int <= baudrate_divisor_int`, so the divisor written while
DLAB=1 becomes live on the **next** AXI write, not the one that set it.

# 6. Phase 3 — Memory tests

## 6.1 Structure

One parametrized core, instantiated four times. This is the main DRY win: the
patterns are identical and only the bounds and capability flags differ.

**`sw/tests/memtest_core.c`** — `memtest_region(name, base, size, flags)`:

| Pattern | Purpose |
| --- | --- |
| width sweep | 8 / 16 / 32-bit store+load across a stride grid |
| walking ones | `v <<= 1` over 32 positions, each bit as a word |
| walking zeros | `~v` over 32 positions |
| address-unique | `addr ^ pattern` per word — catches aliased or stuck lines |
| block + checksum | sequential fill, then read back and accumulate a checksum |
| retention | full sweep, then re-check a sample — catches destructive refresh |
| boundary probes | first and last legal word of the region |
| no-leak-below | first word of region and its immediate predecessor |

All patterns use `%` and `<<` freely — both are hardware instructions (§1.4).
No `long long` division anywhere.

## 6.2 Per-region instantiations

| File | Region | Constraint |
| --- | --- | --- |
| `t_imem.c` | `0x0000_0000` / 32 KB | **writes restricted to `[__imem_image_end, 0x0000_7FFF]`**. Boundary probes at `0x0000_7FF8`. |
| `t_dmem.c` | `0x0001_0010` .. `0x0001_7FFF` | full sweep; scratch must not collide with the stack growing down from `0x0001_8000` |
| `t_iccm.c` | `0xEE00_0000` / 64 KB | **conditional on Phase 0**; write-before-read always (§2.1) |
| `t_dccm.c` | `0xF004_0000` / 64 KB | **conditional on Phase 0**; write-before-read always (§2.1) |

## 6.3 `t_bus.c` — bus and decode tests

Asserts that unmapped regions return an AHB ERROR:

| Address | Expectation |
| --- | --- |
| `0x2000_0000` | AHB ERROR — `sel_def` |
| `0x1000_1000` | AHB ERROR — reserved, no slave |
| `0x1000_4000` | AHB ERROR — **AES base, not decoded** |
| `0x1000_0FF8` | last word of the UART window — must **not** error |
| `0x0000_7FFC` / `0x0001_7FFC` | last word of the IMEM and DMEM regions — must **not** error |

Including `0x1000_4000` here is deliberate. It turns "AES is not integrated" from
a comment into an **executable assertion**. When Phase 5 lands and the decode is
added, this test fails, which is the correct behaviour — it is the tripwire
that proves Phase 5a actually took effect.

Note the AHB ERROR raises an exception on VeeR. **Verified 2026-10-17 — see
§5.3.1 of the consolidated sections:** the error propagates
`hresp → axi4_to_ahb.sv → lsu_axi_rresp → bus_rsp_read_error →
lsu_pmu_bus_error`, and the exception is **imprecise**. Therefore:

- the CPU-issued layer is viable — the CPU really does trap;
- **`mepc + 4` must not be used to resume**, because `mepc` does not reliably
  identify the faulting instruction for an imprecise store error;
- the flag-guarded trap handler clears the expect-flag and jumps to a **fixed
  safe label** in `main`;
- for a store to an unmapped address the data outcome is undefined and does not
  matter;
- `tb_ahb_cycle_monitor`'s `bus_err == 0` and `def_sel == 0` equalities must be
  parameterized (§6.2) or every one of these runs fails the monitor gate.

The **TB-injected layer** runs in parallel: the testbench drives the unmapped
access directly and asserts the ERROR response on the bus, giving a bus-level
proof that does not depend on trap semantics at all.

## 8.2 5b — `t_aes.c`

Register map, from `rtl/aes/aes_axi_slave.v:85-103`, all 32-bit, 4-byte spaced:

| Register | Offset | Read | Write |
| --- | --- | --- | --- |
| CONTROL | `0x00` | `0x0000_0000` | bit 0 START, bit 1 CLEAR DONE/IRQ (both need `write_strb[0]`) |
| STATUS | `0x04` | `[0]` busy, `[1]` done | ignored |
| KEY0..KEY3 | `0x08`..`0x14` | `key0_reg`.. | byte-strobe via `apply_wstrb` |
| DATA0..DATA3 | `0x18`..`0x24` | `data0_reg`.. | byte-strobe |
| RESULT0..RESULT3 | `0x28`..`0x34` | `result0_reg`.. | **read-only** |

Word order, from the comments in the RTL:
`key = {KEY3, KEY2, KEY1, KEY0}`, `aes_text_in = {data3, data2, data1, data0}`.

Known-answer vector, lifted from the already-proven `tb_aes_axi_slave.sv:361-381`:

```
key         00010203_04050607_08090a0b_0c0d0e0f
plaintext   00112233_44556677_8899aabb_ccddeeff
ciphertext  69c4e0d86a7b0430d8cdb78070b4c55a
```

Cases: KEY/DATA readback; CONTROL START → STATUS busy=1 → poll for done;
RESULT0..3 match the vector; `aes_irq` asserts; CONTROL bit 1 clears done and
IRQ; RESULT writes are ignored; START while `busy_reg` is set is ignored
(`aes_axi_slave.v` gates it); byte-strobe partial writes to KEY/DATA; default
offsets read `0x0000_0000`.

# 12. Definition of done

The suite is complete when all of the following hold, each with a surviving log:

1. `make all` builds clean; gates **G1–G15** all PASS.
2. `make sim` emits `P2_TB2_RESULT: PASS` and `AHB_RW_MONITOR: PASS`.
3. Every test in `.test_list` has an entry in the DMEM results table with a
   named, non-zero-on-failure code.
4. The UART transcript contains one line per test.
5. A deliberately broken test is shown to produce: a named UART line, a
   non-zero table entry, correct `first_fail_idx`/`first_fail_code`, and
   `P2_TB2_RESULT: FAIL`.
6. Coverage: IMEM, DMEM, ICCM, DCCM (if Phase 0 permits), UART registers,
   bus/decode behaviour.
7. No test accesses an address the fabric does not decode, except the
   deliberately-asserted ERROR cases in `t_bus.c`.
8. Every claimed PASS cites its log line. Every FAIL cites its waveform.
