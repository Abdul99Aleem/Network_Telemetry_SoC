### N3 — Blocker: `/opt/riscv` contains **no RV32 runtime**, so spec §8.2's `LDFLAGS` will not link

```console
$ riscv64-unknown-elf-gcc --print-multi-lib
.;                                  # single multilib only
$ readelf -A  .../16.1.0/libgcc.a        -> Tag_RISCV_arch "rv64i2p1_..."
$ readelf -h  /opt/riscv/riscv64-unknown-elf/lib/libc.a
  Class: ELF64  Machine: RISC-V          # libc.a members are ELF64
$ readelf -A  .../lib/libc.a              -> Tag_RISCV_arch "rv64i2p1_..."
```

* `libgcc.a` and `libc.a` are **RV64/ELF64 only**; there is no
  `rv32imc/ilp32` multilib directory.
* The RV32-capable toolchain recorded in
  `doc/RISC_V_GNU_Toolchain_...md` §3 at `/root/tools/riscv-gnu/2023.04.29`
  returns **`Permission denied`** for the `student` account.
* VeeR's own `program.hex` rule for C tests needs
  `third_party/picolibc`, which is an **empty submodule**.

Spec §8.2 freezes `LDFLAGS` with **`-nostartfiles` only**. That still passes
`-lgcc` and `-lc` to the linker. Because both are *archives*, nothing is
pulled unless a symbol is referenced — so a pure 32-bit program with no libc
calls links today. The moment anything needs `memcpy`, `printf`, or a 64-bit
helper (`__udivdi3`), the link aborts with an ELFCLASS64/ELFCLASS32 mismatch.

⇒ **Amendment A1 (feed back to spec rev 1.6):** `LDFLAGS` must add
`-nostdlib`, and the firmware must supply its own `_start` + `memcpy`/
`memset`/`memmove`. This makes a missing helper a *loud, immediate* link
error instead of an archive-arch mismatch deep inside ld. Never add `-lgcc`.

> **VERIFIED 2026-09-26 (both halves).** fw0 links to exit status 0 with
> `-nostartfiles` alone, confirming the archive argument above; a test file
> using a 64-bit divide then fails exactly as predicted
> (`libgcc.a(div.o): file class ELFCLASS64 incompatible with ELFCLASS32`), and
> fails cleanly with `undefined reference to __udivdi3` under `-nostdlib`.
> `sw/Makefile` uses A1 and **G7** asserts the link is freestanding.
> Full evidence: `doc/Fw0_C_Toolchain_Build_and_Gate_Record.md` §6.
> The risk row for this finding is therefore downgraded High → Medium: it is a
> *future* failure mode, not a present blocker.

### N6 — `objcopy -O verilog` emits `@` from the section **LMA**, not the VMA

**Found while building `dmem.mem` (Step 2).** With the spec §6.2 command
`--change-addresses=-0x00010000`, the output was:

```verilog
@FFFFFFFFFFFF029C
EE FF C0 00
```

`.data` has `VMA = 0x00010010` but `LMA = 0x0000029C`, so the shift computed
`0x29C - 0x10000` — a negative array index, out of range for the 32 KB dense
`ahb_sram` array.

The §6.2 command remains **correct for `imem.mem`**: there the LMA *is* the
physically right place (the `.data` load bytes really live in IMEM at
`0x0000029C`, and `startup.S` copies from there). Only the DMEM overlay needs
the VMA, and `--change-section-lma` cannot be composed with
`--change-addresses` (applied after it — combining them yields the un-rebased
`0x00010010`).

**Resolution:** `sw/Makefile` computes the `.data` VMA from `nm`, subtracts
`DMEM_BASE`, and passes the result to `--change-section-lma`. Guarded by
**G9**. Analysis: `doc/Fw0_C_Toolchain_Build_and_Gate_Record.md` §5.1.
**Feed back to spec §6.2 as an amendment.**

### N7 — `objcopy -O verilog` writes CRLF; `\r` is not `$readmemh` whitespace

**Also found while building the images.** Every record ends with `\r\n`:

```console
$ od -c build/imem.mem | head -1
0000000   @   0   0   0   0   0   0   0   0  \r  \n   1   7  ...
```

IEEE 1800 §21.7 lists `$readmemh` whitespace as *{space, tab, newline,
formfeed, comment}* — `\r` is absent, so a strict reader can fold the CR into
the first hex token of the image.

**Resolution:** both image rules run `sed -i 's/\r$//'`; guarded by **G10**.
Analysis: record §5.2. **Feed back to spec §6.2 as an amendment.**

### N9 — `%t`/`$finish` print in **ps**; `$time`, `fsdbreport` and the wave RC use **ns**

**Found while interpreting the PASS timestamp.** The run prints
`[90915000] P2_TB2_RESULT: PASS` and `$finish at simulation time 91015000`.
Under `-timescale=1ns/10ps` with 1 ps precision, `%t` and `$finish` report in
**ps** → the run is **91 015 ns = 91.015 µs**, PASS at **90 915 ns**.
Read as ns, a 90 µs run looks like 90 ms — apparently far past the 1.9 ms
monitor watchdog and the `#2000000` testbench timeout, which would have been
read as a hang that never happened.

**Resolution:** all analysis windows below are in **ns**, matching
`fsdbreport -bt/-et` and the `zoom`/`cursor`/`marker` commands in
`run/fw_wave.rc`. Recorded in the cycle-monitor comments.

### N10 — a bare 4-state `reg` used in a condition silently disables its `always` block

**Found while bringing up `tb/tb_ahb_cycle_monitor.sv`.** `reported` and
`stop_d` were declared `reg reported;` with no initialiser. `reg` is 4-state
and initialises to `X`, and `if (!X)` is **never true** — so the entire
counting block *and* the watchdog were skipped while the module compiled,
elaborated and appeared in the hierarchy normally. The monitor produced no
output at all rather than an error.

**Resolution:** `reg reported = 1'b0; reg stop_d = 1'b0;`. Rule: **any `reg`
used in a condition must be explicitly initialised.** Guarded by the dual-token
gate in `make sim`, which fails if `AHB_RW_MONITOR` is absent.

### 3.1 `sw/linker/veer.ld` (spec §4.3, checklist C)

```ld
MEMORY {
  IMEM (rx)  : ORIGIN = 0x00000000, LENGTH = 32K
  DMEM (rwx) : ORIGIN = 0x00010000, LENGTH = 32K
}
ENTRY(_start)
SECTIONS {
  .text   : { KEEP(*(.text.start)) *(.text*) }     > IMEM
  .rodata : { *(.rodata*) *(.srodata*) }            > IMEM

  /* .data  VMA = DMEM, LMA = IMEM  -> startup.S copies LMA -> VMA */
  .data   : { __data_start = .; *(.data*) *(.sdata*);
              __data_end = .; }  > DMEM AT> IMEM
  __data_load = LOADADDR(.data);

  .bss (NOLOAD) : { __bss_start = .; *(.bss*) *(.sbss*) *(COMMON);
                    __bss_end = .; }                > DMEM

  __stack_top = ORIGIN(DMEM) + LENGTH(DMEM);        /* 0x00018000 */
}
```

* `.data` **VMA = DMEM, LMA = IMEM** — `startup.S` copies LMA→VMA (spec §22
  step 2; companion §PART I's "place `.data` at its final address" no-copy
  form is explicitly permitted by §22 as an fw0 simplification, but the copy
  form is the default because it also works when DMEM is not preloaded).
* Guardrails (spec §9.3, amendment `H.9`):
  `ASSERT` no section at `0xEE00_xxxx`/`0xF004_xxxx`;
  `ASSERT` `_start == 0x00000000` (must equal `reset_vec=0`);
  `ASSERT` `.bss` end + stack do not collide; region overflow asserts.
* Link map emitted to `sw/build/firmware.map`.

### 3.2 `sw/src/startup.S` (spec §22, frozen order `D8`)

1. `la sp, __stack_top` (DMEM top, 16-byte aligned).
2. Copy `.data` LMA→VMA.
3. Zero `.bss` — the `NOBITS` rule (§6.2.3): *no conversion tool can ever
   produce these bytes*, so both `startup.S` and the loader pre-fill cover it.
4. `call main`.
5. On return, write the Phase-2 PASS magic to the DMEM mailbox
   (`u_dmem.mem[0]='P'`, `[1]='2'`, `[2]=8'hFF`) — spec §22 fw0: fires the
   **existing** `tb_veer_p2_soc` monitor with **zero monitor changes**.
6. `1: j 1b` — park.

### 3.3 `sw/src/main.c` — step 1 proper

Written so that each construct produces a **waveform-observable bus cycle**
(this is what step 3 will measure):

```c
int main(void) {
    /* 1. .data / .bss sanity      -> proves startup.S ran               */
    /* 2. fill a uint32_t[] in .bss -> LSU WRITE cycles to DMEM          */
    /* 3. checksum -> store to DMEM -> LSU WRITE cycles                  */
    /* 4. reload from DMEM, compare -> LSU READ  cycles                  */
    /* 5. write mailbox magic -> existing Phase-2 monitor fires          */
    /* fw2/fw5 later: MMIO to UART @0x1000_0000 / AES @0x1000_4000      */
}
```

`sw/include/soc.h` holds the frozen map as MMIO accessors:

```c
#define IMEM_BASE 0x00000000u
#define DMEM_BASE 0x00010000u
#define UART_BASE 0x10000000u   /* spec §9, §10.1 — fw2 */
#define AES_BASE  0x10004000u   /* spec §10.5        — fw5 */
#define MMIO32(a) (*(volatile uint32_t *)(uintptr_t)(a))
```

**Constraint from Amendment A1:** avoid `uint64_t` arithmetic that GCC
lowers to `__udivdi3`/`__ashldi3`, and avoid struct copies that lower to
`memcpy`, unless `lib.c` provides them. This is checked by the link step —
a violation fails loudly.

## 4.1 Structure (spec §8)

```text
Makefile              (root delegator: firmware inspect mem veer-config rtl sim run all clean)
sw/Makefile           (compiler flags; targets: elf dis ihex mem inspect manifest clean)
sim/Makefile          (VCS env; veer-config rtl sim run)
sim/filelist.f        (references build/snapshots/p2_soc — D6, replaces the /tmp hardcode)
```

`sw/Makefile` uses the §8.2 frozen variables verbatim, **plus Amendment A1**:

```make
CROSS_COMPILE := riscv64-unknown-elf-
CC := $(CROSS_COMPILE)gcc ; OBJCOPY := $(CROSS_COMPILE)objcopy
OBJDUMP := $(CROSS_COMPILE)objdump ; READELF := $(CROSS_COMPILE)readelf
MARCH := rv32imc_zicsr_zifencei          # D7 / H.8
MABI  := ilp32
CFLAGS  := -march=$(MARCH) -mabi=$(MABI) -O0 -g -ffreestanding -fno-builtin -Wall -Wextra
LDFLAGS := -march=$(MARCH) -mabi=$(MABI) -nostartfiles -nostdlib \
           -T linker/veer.ld -Wl,-Map=$(BUILD)/firmware.map      # <- -nostdlib = A1
```

Image rules per **spec §6.2** (this is the part that must be exact):

```make
$(BUILD)/firmware.ihex: $(BUILD)/firmware.ihex                    # delivery ONLY, never $readmemh (H.1)
	$(OBJCOPY) -O ihex $< $@

$(BUILD)/imem.mem: $(BUILD)/firmware.elf                          # D11 / H.3
	$(OBJCOPY) -O verilog --verilog-data-width 1 \
	  --only-section=.text --only-section=.rodata --only-section=.data \
	  --change-addresses=-0x00000000 $< $@

$(BUILD)/dmem.mem: $(BUILD)/firmware.elf
	$(OBJCOPY) -O verilog --verilog-data-width 1 \
	  --only-section=.data \
	  --change-addresses=-0x00010000 $< $@
```

* `--verilog-data-width 1` because `ahb_sram.mem` is `reg [7:0] mem[0:32767]`
  (**H.3** width rule: N must equal the array's word width in bytes).
* `--change-addresses` rebases `@` to each array's **index 0** (**H.3**
  rebase rule) — an `@00010000` marker against a 32 KB array addresses index
  65536, out of range. Spec §14 makes "out-of-range `@`" a hard TB failure.
* `.bss` is `NOBITS` and appears in **neither** image.

## 5.2 The read/write-cycle monitor (new, additive)

Spec §14 wants an unambiguous terminal token in the
`P2_TB2_RESULT: PASS/FAIL` style; §22 fw0 requires the **existing** monitor to
fire unchanged. To satisfy both without touching the existing monitor, add a
**separate** module `tb/tb_ahb_cycle_monitor.sv`:

```systemverilog
// ---------------------------------------------------------------------------
// Sampling rule (AHB-Lite): an ADDRESS PHASE is accepted in cycle t iff
//     HTRANS != IDLE  &&  HREADY == 1
// Sample on posedge core_clk while rst_l && !done.
//
// Classify by the accepted address (decode mirrors ahb_interconnect.sv:122-123):
//     addr[31:15] == 17'h0000 -> IMEM      addr[31:15] == 17'h0002 -> DMEM
//     addr[31:12] == 20'h10000 -> UART (0x1000_0000, fw2)
//
// IFU (fetch-only, never writes)          LSU (read/write)
//   imem_rd += ic_htrans!=0 && ic_hready    by accepted address:
//                                             dmem_rd / dmem_wr  (.bss, .data copy dst, array)
//                                             imem_rd            (.data LMA read during copy)
//                                             imem_wr            expected 0 under D11 —
//                                                    .bss VMA is in DMEM, so nothing is
//                                                    ever stored into IMEM; kept as a canary
//
// bus_err  : any cycle where ic_hresp || lsu_hresp is 1
// ---------------------------------------------------------------------------
```

> **Do not count with `hsel && hreadyout` on the same cycle.** `hsel` is an
> *address-phase* signal while `hreadyout` completes the *data phase* — pairing
> them mis-counts by one. `doc/Phase2_AHB_Fabric_Completion_Record.md` §4.1
> and §4.3 record exactly this class of bug ("BFM sampled AHB responses a cycle
> early"), so the address-phase acceptance rule above is the correct one.

Prints `[TB] AHB_CYCLES imem_rd=N imem_wr=N dmem_rd=N dmem_wr=N uart_wr=N bus_err=0`
and its own token `AHB_RW_MONITOR: PASS` only when
`dmem_wr ≥ N₁ ∧ dmem_rd ≥ N₂ ∧ imem_rd ≥ N₃ ∧ bus_err == 0`.

The flow gates on **both** tokens:

```csh
grep -q "P2_TB2_RESULT: PASS"        sim.log   # spec §22 fw0 — unchanged monitor
grep -q "AHB_RW_MONITOR: PASS"       sim.log   # this plan — read/write proof
```
